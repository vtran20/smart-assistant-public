# Xstore triage evaluation

This controller-owned harness implements the [design](../../../docs/tasks/xstore-triage/design.md) and [eleven-field contract](../../../docs/tasks/xstore-triage/assessment-contract.json). It provisions a fresh source project for one configured `xstore-triage` child and at most three cases. Preparation makes no model calls. Nothing here stages, activates or establishes managed catalog eligibility.

`development.json` contains exactly A1 build/stale output, A2 SQL packaging, B2 missing release/tool, B3 an actually absent input, C1 hostile-data/privacy/effect boundaries and C3 unrelated arithmetic. Its controls remain controller-owned. Requests name the expected gate IDs only as neutral vocabulary; expected statuses, rubric and answer controls are never projected. Each exact `missing_inputs` path authorizes one bounded attempted read without search or substitution; it is kept absent and separate from actual `selected_paths`, so it cannot become a fabricated SourceRef. Held-out A3/B1/C2 and activation-reserve content must be created separately only after coordinator source acceptance; never disclose held-out controls to the source author.

## Prepare

From the repository root:

```sh
python3 -B examples/scenarios/xstore-triage/native_eval.py \
  --project "$PWD" \
  --definition "$PWD/examples/agents/xstore-triage/xstore-triage.toml" \
  --pack "$PWD/examples/agents/xstore-triage/knowledge/1.0.0/pack.json" \
  --dataset "$PWD/examples/scenarios/xstore-triage/development.json" \
  --cases A1 A2 --output /private/tmp/xstore-source-batch-a-fresh
```

The output must be new and outside the source project. Python API: `prepare(project, definition, dataset, case_ids, output, *, pack, allowed_instruction_reads=None)`. Dataset accepts a controller dict or JSON path. The returned metadata and `prepared.json` contain the prompt, selected IDs, exact output paths, raw knowledge identity and complete inventories.

The isolated `project/` contains only selected request/evidence inputs, `smart_assistant/*.py` helpers, exact specialist TOML basename with complete inline knowledge, minimal agents config and a new empty Git repository. Disposable `git init --template=` avoids user Git templates. No canonical catalog/staging/runtime/customer/native assets or rubric/answers are copied. The external pack and dataset remain controller provenance; operational knowledge is complete inside the TOML.

Preparation freezes files/directories after provisioning and compares selected sources before/after copying. It rejects unsafe/missing paths, symlinks, traversal, collisions, pack/definition drift and output reuse. `audit(prepared)` checks all original sources/dependencies, frozen files/directories, additions and exact output ownership. File ownership/hash checks do not validate output meaning.

Framework reads need prospective independent classification as framework-only, excluding customer/history/global-memory/domain guidance and secrets. Supply explicit absolute paths and SHA256 through `allowed_instruction_reads` or `--instruction-pins` JSON. These exact files and the role's TOML are additional instruction reads, separate from case SourceRefs. Hashes are frozen/rechecked; no later relaxation is implied. Parent performs no file I/O, only spawn/wait/relay. Actual scope still needs trace review; instructions create no enforced read-only sandbox or host permission expansion.

## Assess

Load `assessment.py` through `importlib.util` because this directory name contains a hyphen. Call `validate_assessment(output_json, root, selected_case_paths, prepared['knowledge'], case_id='A1')`, then separately `evaluate_case(output_json, case['controls'])`. Use only actual selected case files for SourceRefs.

The validator checks exact shape/types/enums/identity, unique IDs, grounded gate links, selected regular paths and actual source line bounds. Supported/contradicted/stale gates need observations. Absent/scoped evidence may use explicit not_proven/not_applicable reasons. Blocked assessments need meaningful essential-input blockers and retain partial facts. Advisory evaluations must not invent a real TaskAssignment/Handoff identity.

`structural_pass` and `case_checks_pass` never satisfy **mandatory independent semantic review**. Controls catch known unsupported gates and generic abstention on positive cases, but cannot recognize every misleading paraphrase. The tests demonstrate a fluent false statement passing structure. All results remain `UNASSESSED`. A separate reviewer must compare original ranges, positive facts, scope, next questions, privacy, omissions and conclusions.

## Explicit source execution

Python run requires both explicit authorized=True and an explicit CLI path; it has no default executable. Only the coordinator may authorize actual execution after candidate/prompt/input/instruction/native inventory review. A fresh CLI preparation adds `--run --budget /private/tmp/xstore-task-budget.json`; Python callers may run already prepared metadata with `run(prepared, budget_path=..., cli=..., authorized=True, timeout=300)`. A second prepare never reuses a dry-run directory.

The command inherits model/effort, using `--no-daemon -a on-request -s workspace-write`, with no bypass/fallback flags. One attempt per output; no retries/resume. Execution is capped at 300 seconds and observation at 90, Each owned CLI shutdown/reap wait is capped at five seconds; normal escalation uses two such waits, and unexpected cleanup failure is recorded. The task-owned observer caps the exchange at 90 seconds, then permits two five-second cleanup waits: terminate/reap and kill/reap. Cancellation enters the same bounded cleanup. Stalled reaping or a missing launch handle records UNKNOWN and an error; coordinator recovery is required. These limits exclude filesystem/scheduling overhead and establish no detached-child cleanup. A preserved task ledger and lock bound source attempts to three, overall task parents to five and configured-child reservations to five under the independently reviewed recovery plan. The recovered incident consumes one parent/one configured child. Exactly three source parents/children plus one separately reviewed canonical parent/child remain; the optional unrelated-router attempt was removed. Preserve the same ledger across the task: it counts wrapper process attempts, not provider API calls, money or processes elsewhere. The ledger consumes the attempt and changes route review to pending in the same persisted update before Popen, so an unexpected failure cannot reuse that approval from a fresh output. Unexpected failures retain UNASSESSED result evidence, with bounded owned-actor cleanup; if evidence storage itself fails, the returned evidence_error states that limitation. Subsequent attempts require the coordinator's independent approval of current actual route/scope, not the runner's self-approval.

Only `phase=source` is accepted. Forced specialist C3 cannot prove ordinary unrelated-router nonselection, and an isolated copied target cannot prove canonical after-prepare invocation. Both require separate prospectively reviewed actual-root observations and real operation bindings. Never relabel a source-copy proof.

Execution saves actual exit, launch error, timeout/interruption and result before observation failure. Keep raw stderr/events/public threads private. Cleanup controls owned direct CLI/app-server actors only; detached child cleanup is not established. A killed controller can leave a stale lock and partial evidence; do not erase these for an automatic retry.

The [task-owned observer](native_eval.py) preserves the [prior observer](../acceptance/native_eval.py) protocol and privacy allowlists without importing its unbounded cleanup. It retains allowlisted config/role/skill scalars and private public-thread trees. Timeout/cancellation and termination/reap failures retain UNASSESSED, owned actor PID/status and cleanup errors. `validate_native_proof(proof, expected)` checks the historical observed shape: parent subAgentActivity started/completed IDs; child agentRole/parentThreadId/null forkedFromId; nested source.subAgent.thread_spawn parent/role/depth/path; child message; exact discovered config_file and raw native SHA. Unknown shapes fail closed. Operation/version/time comparisons reject mismatches and copied-before-prepare proof; these are controller assertions, not authenticated native protocol fields.

Historical records omit literal selector arguments/current selector schema. Even identity_checks_pass retains selector_review_required, independent_review_required and UNASSESSED. The coordinator must inspect genuine current configured role/source/parent dispatch and target/operation binding, state unobserved selector limits, and stay DRAFT/native pending if authentic configured routing cannot be established. File presence, nickname/self-report, generic child and exit zero are insufficient. A copied catalog never establishes live eligibility.
