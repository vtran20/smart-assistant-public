# Scoped learning and research during delivery

Use with [project learning](agent-learning.md) and the [approved design](superpowers/specs/2026-11-02-tom-jerry-orchestration-design.md). This is file-based work during an authorized task, not background service, model training or permission grant.

## Research a missing fact

Record the question/blocked decision, allowed sources/actions, project/version, finite effort bound and verification method. Read owning-project source and applicable knowledge first. Inspect authoritative current external sources when needed within authorization. Research grants no new access or permission to message people.

Save source/version/date and supported facts separately from conclusions/hypotheses. Keep contradictions visible. An unverified Xstore API must not become an implementation assumption. Independently review material conclusions before design use. Missing facts block affected work while independent authorized tasks continue.

The [synthetic research packet](../examples/learning/research-packet.json) is a field example, not observed evidence. Private captures belong in the owning project's ignored evidence store; shared references must be sanitized.

## Capture and retrieve lessons

Read the short index and only matching records. Revalidate scope, versions, evidence and assumptions against current source. Apply applicable user_confirmed/agent_validated entries without routine promotion questions. Candidates remain investigation leads; superseded records retain replacement references. Knowledge status grants no permission and satisfies no review/activation gate.

Record ID/date/status/source/scope/finding/applicability/evidence/checks/revalidation/supersedes in existing owning structures. Consolidate duplicates. User statements are user_confirmed; agent_validated requires actual evidence. Never label agent review as human approval.

Customer rules, architecture and raw diagnostics stay in the customer project. Sanitized orchestration lessons belong to Smart Assistant; generalized Xstore patterns may be proposed for the shared KB. Credentials are never context. Generated Codex memories and vendor plugins remain unchanged.

## Shared Xstore guidance

Read actual library rules and selected file hashes. The supplied Markdown KB differs from the installed pack resolver; use the read-only selector, do not claim onboarding or invent a commit. Updates never silently repin active tasks.

Shared contributions require recorded maintainer authorization. This project's standing scope (local historical archive: `evidence/p15/standing-authorization.json`) and reviewed local policy application (local historical archive: `evidence/p15/shared-policy-applied.json`) record the approved reconciliation. Within an applicable scope, independently reviewed and validated sanitized contributions need no repeated routine approval. Missing grants, uncertain reuse, out-of-scope changes and actual mandatory human acceptance remain explicit decision points; keep unsupported contributions local.

Contributions must be reusable, source-traceable, version-scoped, independently reviewed, validated and sanitized. Remove customer data, private URLs, environment values, store/register IDs, secrets and payment data. Do not universalize customer business rules.

## Improve a procedure or role

The [synthetic proposal](../examples/learning/improvement-proposal.json) records an observed failure and one bounded versioned change. Freeze baseline/candidate/rubric, representative regressions and independently authored fresh held-out cases when needed. Self-authored memories and disclosed answers are not ground truth.

Compare actual outcomes and independently review regressions/limits before the managed activation lifecycle. Missing native proof leaves DRAFT. Preserve rollback and failed history. Authors cannot change evaluators, permission boundaries or release controls to approve themselves. No unbounded model runs or expanded correction/concurrency limits.

Scheduled learning, cross-chat wakeups and publication need their own authorization/implementation. This runs at active task checkpoints; no universal future behavior or unattended learning is claimed.
