# P15 scoped learning and controlled improvement plan

Spec: [approved architecture](../specs/2026-11-02-tom-jerry-orchestration-design.md), section11. Existing project learning and user autonomy policy remain binding. No model retraining or background service.

## Scope and ownership

Implement reusable procedures/templates for research packets, scoped lesson capture/retrieval and prospective improvement evaluation. Reuse docs/agent-learning.md and existing task evidence rather than create a parallel memory engine. Customer facts/evidence stay in the owning project. Root owns project instructions/shared policy; worker needs exact-file assignment before edits. Generated memories and vendor plugins remain read-only.

## Tasks and verification

1. Inspect actual learning policy, KB README/promotion/security rules and existing governance skill. Inventory overlaps and define ID/date/status/source/scope/finding/applicability/evidence/checks/revalidation/supersedes. Unknown conclusions remain candidate; never invent human review.
2. Write failing fixture checks for research provenance, unsupported conclusions, version mismatch/conflicts, scope leaks, missing review and unsafe candidate/superseded reuse. Add a genuine fresh-context retrieval exercise on sanitized fixtures, honestly identified as generic context rather than a configured managed role.
3. Implement existing procedure references and sanitized capture/retrieval/deduplication/supersession examples. Reuse scoped user_confirmed/agent_validated knowledge within authorization; knowledge grants no permission or activation.
4. Prepare exact shared-KB policy reconciliation: standing authorization for sanitized independently reviewed reusable guidance, preserve uncertain reuse/human acceptance and all privacy requirements. Independently review exact diff before local KB changes. No publish/push; shared writes remain disabled until policy validation. An unresolved scope conflict yields a local candidate.
5. Define versioned improvement record: observed failure, bounded change, exact baseline/candidate, representative regressions and fresh held-out cases, independent assessment, native/deployment acceptance and rollback. Author cannot alter evaluator/release controls to self-approve. No unattended runs or automatic active-task repin.
6. Independently review artifacts; record findings/dispositions, re-review changes, run fresh reference/fixture checks and actual retrieval observation. Report native/runtime/KB gaps separately. No claim of universal future behavior.

Host approval governs writes outside current roots. Routine reviewed changes within approved scope need no repeated user consent. Existing required review/testing/activation and actual human acceptance gates remain intact.
