# P05 agent lifecycle design

## Scope and acceptance

Implement the approved P05 APIs on baseline 04c8a5b: `validate_agent_definition(path: Path) -> GateResult` and `stage_agent(project_root: Path, definition_path: Path, record: CapabilityRecord) -> CapabilityRecord`. Owned files are agent_lifecycle.py, its tests, manage-agent skill, examples/agents, and this package's task/evidence directories. P02 contracts, catalog, DeploymentStore, root native assets and account permissions are unchanged.

Accept only regular nonsymlink TOML definitions whose name is a contract-compatible identity and whose description and developer_instructions are nonblank. Instructions must explicitly contain the ordered project cycle: design → implement → independent review → feedback → test → repeat. Required schema comes from [official native agent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents), fetched by root 2026-10-13. This helper supports those three fields only. Model and model_reasoning_effort overrides fail with unobserved_catalog because no observed available catalog is passed to this frozen API; no guessed allowlist. Other optional config fails with unsupported_field, including permission/approval/sandbox overrides. Native optional-schema coverage is intentionally incomplete.

Normalize public records through P00 codecs. Stage only AGENT/DRAFT identity matching the definition, with a safe `.codex/agents/<basename>.toml` target. Refuse identity and target collisions against the current catalog and all native project agent names. A registered same identity may be replaced only with the same kind/target and a new version. Existing version directories are immutable. Reject paths outside the project, native discovery sources, journal overlap, symlinks, nonregular files and invalid roots before reads/copies. Catalog inspection does not grant activation authorization.

Create a private immutable copy at `capabilities/staging/agents/<id>/<version>/<target-basename>`. Hash the full bytes in the complete one-file manifest using the native target basename, matching P02. Return a fresh normalized record pointing to those bytes, with their manifest hash and cleared validation/evaluation/discovery/rollback references. No catalog write, prepare, native copy or passing evaluation occurs. Tests use temporary roots; private staged files are never committed.

## Management and verification

Chat creation chooses a narrow responsibility from user intent and records triggers, boundaries, inputs, output contract and actually available tools. The manage-agent skill uses the public helpers and P02 DeploymentStore APIs. Evaluation must bind observed ordinary/out-of-scope/missing-tool outcomes to the candidate manifest. Structural success does not satisfy evaluation. Prepare only with scope authorization and independently reviewed, manifest-bound validation/evaluation evidence. Root runs fresh installed-native sessions, binds discovery and invocation to operation/identity/version/manifest/client/session, finalizes only genuine proof, and restores failed uncommitted preparation. Disable requires fresh absence proof. Rollback of committed assets is a newly staged version using previous bytes and a new transaction/probe.

Meaningful unit tests cover missing fields, malformed TOML, cycle omissions, unsupported config, special/symlink/outside files, record normalization, duplicate identity/target, unsafe paths, immutable versions, fresh proof clearing, complete manifest and P02 prepare rejection without evaluation. Root independently reviews the frozen candidate and conducts isolated installed-client probes using examples/agents. Follow design → implement → independent review → recorded feedback → fresh tests → repeat. Native behavior and independent review remain pending at implementer handoff.

## Independent-review correction design

P05-R1: prepare bytes in an invocation-owned `.stage-<random>` directory under the private agent staging parent. Flush/fsync the file, compute the complete target-basename manifest and normalize the return record before publishing. A project-private per-agent `.stage.lock` serializes the absent-version recheck and atomic directory rename. Keep the lock file stable; removing it could split concurrent lock ownership. Existing successful versions stay immutable. On open/write/fsync/hash failure or a concurrent publication collision, remove only that invocation's unique temporary directory. No unsuccessful final version remains, so the same version can retry after a transient failure. Locks/temporary copies are private staging resources, outside native discovery and transaction storage; no catalog/native writes occur.

P05-R2: search for a whole ordered sequence containing an actual independent-review phrase instead of selecting the first unrelated review word. Support independent review/review independently/review (independent), and consider later stage occurrences. Missing/unordered cycles still reject.

P05-R3 (coordinator finding C1): narrowly reject clear operative review/testing waivers (optional, unnecessary, not required, no review/testing required, no need for review/testing) alongside the existing affirmative skip checks. Negated prohibitions and `No independent review is complete without tests` remain valid. This remains lexical structure validation, not full NLP or proof of obedience.

Verification uses meaningful failing regressions for each reproduced finding, transient failures after partial real I/O, coordinated concurrent publication, successful same-version retry and exact native basename hashes. Preserve original candidate/hash/review evidence; create new corrective hashes and fresh targeted/full checks, then root obtains scoped independent re-review and resolves feedback. Native evaluation remains root-owned and pending.

### Remaining direct-waiver grammar correction

Scoped re-review accepted R1/R2 but kept C1/P05-R3 open after reproducing `No tests required`, `No independent review required` and `No need to test`. The narrow corrective design permits omitted is/are only in direct no-required/no-needed/no-necessary forms and recognizes no-need-to review/test/verify directives, including independently review. Preserve compound negative prohibitions and explicit positive requirements. No staging, permission, schema, API or native behavior changes. Add RED subtests for all three reproductions and ordinary needed/necessary variants, then fresh targeted/full tests and a new exact product manifest; root obtains scoped re-review.
