# P01 — task state and scoped context

## Outcome and ownership

Implement the P00 `TaskRecord` persistence and scoped `ContextBundle` reader in `smart_assistant/state.py` and `smart_assistant/context.py`. The public store API is `TaskStore(root, completion_check=None)`, `create`, `read`, `update`, plus `resume_failed(record, expected_revision)` for an explicit failed-to-running event. Context uses `load_context(root, project_id, role_id=None)`. P03 supplies completion evidence through the injected checker; P01 owns transition legality. Only P01 files are changed.

## Task store

Records live at `<root>/tasks/<task_id>.json`; persistent locks at `<root>/locks/<task_id>.lock`. IDs use the frozen P00 ID syntax, so they cannot name parent paths. A root path is trusted as an input but checked and canonicalized through its existing ancestors for every operation. macOS `/tmp` and `/var` aliases to `/private/tmp` and `/private/var` are accepted; other symlink components, including an arbitrary alias or the root itself, are rejected. The canonical absolute root is traversed from `/` with `O_DIRECTORY|O_NOFOLLOW` directory descriptors. All descendants are opened relative to retained parent descriptors with no-follow semantics; records, contexts, and locks require regular-file descriptors. Record/context opens use `O_NONBLOCK` to reject FIFOs before any wait. Each mutation holds an exclusive `flock` on a stable per-task lock inode through read, revision check, validation and atomic replacement. Lock files are retained; unlinking an unlocked file could let competing writers lock different inodes. A rejected mutation leaves the previous record untouched. `read` only reads and validates an existing record; it creates no directories or locks.

`create` accepts a structurally valid record, persists revision 1 and refuses a preexisting ID. It rejects completed creation to prevent bypassing the completion gate. All store decisions consume a fresh typed record reconstructed from P00's validated wire data; caller-provided plain strings for enum fields cannot bypass gates. `update` requires the caller's `expected_revision` to equal the stored revision and the proposed record revision to equal that expected value; the store writes expected+1. It requires immutable ID and request identity/project, enforces the status transition table, and rejects ordinary failed-to-running. `resume_failed` is the sole failed-to-running transition and uses the same CAS. Same-status updates are allowed for progress except terminal states. Completed and cancelled are immutable terminal states. For a transition into completed, absent checker or any result other than a valid, passed `GateResult` denies the write. Checker exceptions propagate without a write. The checker sees an isolated copy of the proposed completed record at the new revision; callback mutation cannot change the stored record. Reads verify the decoded task ID matches the filename.

An accepted write serializes through P00 `to_dict`, creates a temporary file relative to the retained tasks descriptor, writes and fsyncs JSON, calls `os.replace` with source/destination directory descriptors, then fsyncs the directory descriptor. On failure before replacement the temporary file is removed relative to that descriptor and the old record stays valid. Callers are never given a partially written record. Read errors distinguish missing records from malformed/invalid records. A parent component swap can at worst detach the opened directory; it cannot redirect operations to a different directory. The store also verifies the retained tasks/locks directory identities before commit and aborts if detached.

## Context selection

Optional project context lives at `<root>/context/projects/<project_id>.json`; optional role overlay at `<root>/context/projects/<project_id>/roles/<role_id>.json`. Both files are exact P00 `ContextBundle` JSON objects with `project_id` equal to the requested project. Project facts must use scope `project:<project_id>`; role facts must use `role:<role_id>`. The role file is nested under its project to avoid cross-project selection. A missing project or role file contributes empty preferences/facts. When both exist, preferences are shallow-merged with role keys taking precedence; facts preserve order, project first and then role. Source references and observation timestamps remain unchanged. Malformed JSON, wrong schema, mismatched project or fact scope, symlinks, and unsafe IDs raise validation errors, never become empty context. The loader reads only the selected project and role files and writes nothing.

## Verification and review

TDD tests use `TemporaryDirectory` and P00 synthetic fixtures. They cover stale writers, two explicitly synchronized processes, interrupted replacement, lock retention, status table and explicit resume, gate denial, read without mutation, path/symlink safety, project and role isolation, missing optional files and malformed scope. Run targeted `python3 -m unittest tests.test_state tests.test_context -v` and full discovery. Independent review checks lost updates, lock lifecycle, filesystem escape and context leakage; findings and resolutions are recorded in `docs/evidence/p01/feedback.md`.
