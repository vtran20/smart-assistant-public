# P03 — preflight and completion evidence

## Scope and intended outcome

Implement only the four APIs in work/p03/implementation-brief.md, using frozen P00 dataclasses, Python 3.11+ and the standard library. P01 owns status transitions and may pass a proposed COMPLETED record. The checker never changes records, runs checks, executes tools or grants permission. Existing task state is not read; tests use temporary files and synthetic records.

## Decisions

`preflight(required_tools, available_tools, requested_actions, authorization)` requires actual sets of nonempty strings and validated P00 records in actual lists. Invalid input raises P00 ValidationError. Missing tools are the sorted union of workflow tools and action-required tools minus observed available tools. Each action needs an exact `(kind, resource_ref)` AuthorizationScope match and HostDecision.ALLOWED. Destinations are opaque exact strings, with no prefix, wildcard or normalization. Absent, different-destination or malformed authorization never implies approval. Pending reasons list missing authorization, nonallowed host decision and missing required action tool. Top-level list entries must retain their declared dataclass type; each validated entry is decoded into a fresh typed copy before policy inspection. Valid wire enum strings normalize without modifying caller input. Tools/roles do not authorize; source_ref is a declared source, not cryptographic proof of user intent.

`snapshot(root, artifacts)` creates sorted copies and hashes current regular-file bytes; supplied digest values are never used as file truth. Duplicate IDs/paths reject. `acceptance_snapshot(criteria, design_path)` creates sorted copies, hashes current design bytes and fingerprints all criterion fields. Both follow P00 canonical JSON fingerprint definitions and raise ValidationError for malformed input or unsafe/unreadable paths. No receipt object is a candidate artifact.

`completion_gate(task)` returns GateResult, including structured diagnostics on malformed records. The top-level input remains TaskRecord; its complete validated wire form is decoded into a fresh typed TaskRecord before any nested evidence is consumed. Valid nested wire dictionaries and enum strings therefore normalize consistently, while malformed wire data retains P00 error diagnostics. Standalone snapshot/acceptance list entries require Artifact/Criterion dataclasses and are also decoded into fresh typed copies; raw top-level dictionary entries raise ValidationError. It requires nonempty unique criteria and nonempty candidate artifacts. Cycles are chronological append-only history: strictly increasing positive cycle numbers; gaps are allowed. Select the final cycle only after verifying order; never fall back to an earlier successful cycle. Earlier failed cycles remain legitimate history, but all records must remain structurally valid. A missing latest review gives `missing_review`; duplicate/descending numbers give `invalid_cycle_history`.

The latest candidate is recomputed from current artifact bytes and must equal its candidate_id. The latest acceptance is recomputed from current task criteria and current design bytes and must equal its acceptance_id. Review and every check must bind to both current fingerprints. Reviewer and implementer references must differ exactly; this is a consistency check, with actual independence enforced by orchestration. Check IDs, finding IDs and disposition finding IDs must be unique. Every finding requires exactly one CORRECTED or REJECTED disposition with nonempty reason and local evidence. Orphan dispositions, unknown criterion references, failing checks, no checks or uncovered criteria fail. Evidence must be present even for passing observation receipts. Check method payloads follow P00 validation.

All design/check/disposition references are safe POSIX relative file paths under the resolved existing absolute artifact_root. No URI, absolute path, backslash, empty/dot/dot-dot component, symlink component or nonregular file is accepted. File reads traverse directory descriptors with O_NOFOLLOW and require regular files, preserving the root anchor during child traversal. Root resolution permits system aliases such as macOS /tmp; the resolved root is opened as a directory without following its final component. Root replacement before its initial opening and concurrent in-place file writes are not made transactional: callers must serialize candidate review/completion with modifications. Standalone acceptance_snapshot uses the design file's parent as its anchor and rejects a symlink design file. Gate checks relative design components under the task root. Candidate paths and file identities (including hardlink aliases) cannot overlap check/disposition evidence: receipts are evidence, not product artifacts. ReviewReceipt has no evidence_ref in the frozen contract, so the structured receipt itself supplies review metadata; external review authenticity remains orchestration responsibility.

Stable domain codes: `missing_review`, `invalid_cycle_history`, `invalid_criteria`, `invalid_candidate`, `stale_candidate`, `stale_acceptance`, `stale_review`, `stale_check`, `same_reviewer_implementer`, `unresolved_feedback`, `invalid_findings`, `invalid_dispositions`, `failed_check`, `missing_criterion_coverage`, `invalid_checks`, `invalid_evidence_path`, `missing_evidence`, `invalid_artifact_path`, `missing_artifact`, `evidence_as_artifact`. P00 structural codes remain unchanged. Diagnostics use `$` paths; results never claim an evidence reference's content is truthful.

## Implementation and verification

1. Write synthetic fixture tests before product code. Observe failures for missing implementation.
2. Implement snapshots/path boundary and completion gate; exercise mutations of artifacts, design, criterion descriptions/methods, receipts, reviews, coverage, cycles and malformed inputs.
3. Implement exact preflight matching and test every host decision, action/workflow tools and scope mismatch.
4. Save targeted and full unittest logs, self-review, byte hashes and feedback record. Commit only owned files and freeze for coordinator independent review.
5. Resolve coordinator findings with failing regression tests, fresh tests and final candidate re-review.

Acceptance: current bytes only; no stale or empty-criteria completion; complete independent-reference review, dispositions and passing criterion evidence; local path containment; exact permission and tool preflight; no side effects outside local reads. Verification commands: `python3 -m unittest tests.test_preflight tests.test_quality -v` and `python3 -m unittest discover -s tests -v`.
