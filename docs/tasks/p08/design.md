## Architecture and alternatives

Use existing v1 TaskAssignment/Handoff, native Codex children and durable coordinator state. Add one explicit filesystem-aware gate in contracts, invoked by the parent before integrating child outputs. A new scheduler/backend would exceed scope. Pure prose without handoff validation would leave revision/ownership failures unchecked. A new child-state schema would needlessly break frozen v1 interfaces. Thus retain v1 records and use scoped native orchestration with deterministic validation.

`validate_handoff(assignment, handoff, artifact_root) -> GateResult` checks typed wire validity, task ID, assignment revision, role, nonempty unique criteria/owned paths, unique artifact IDs/paths, exact-file ownership (no implicit directory prefix grants), current artifact hashes, safe local existing regular files and coverage/evidence references under a trusted absolute artifact directory. The trusted root must itself be canonical (absolute and equal to strict resolution). No cwd-dependent resolution, URI refs, traversal, symlink components or nonregular files. Evidence refs must exist but may be outside output ownership: an independent reviewer/coordinator owns those files. Coverage keys must belong to assignment criteria; ready handoffs cover all assigned criteria with nonempty refs and at least one artifact. Blocked/failed handoffs retain partial output/coverage but never pass the integration gate; require meaningful blocker and next step. Ready handoffs require blocker null and a nonempty next step. The parent checks that the next step requests independent review; the structural helper does not infer intent from natural-language text. Hash/structural coverage does not establish semantic correctness, genuine review or completion. No artifact mutation, task update or authorization side effects. Use existing quality path/hash helpers through a deferred import to avoid a contracts/quality import cycle; preserve frozen schemas and existing error conventions.

## Scope and scheduling

The parent alone changes shared contracts, config/catalog/tracking and durable task state. Before every managed dispatch/resume observe tools, current eligibility and exact version/manifest, load only scoped context and run exact-action preflight. New assets remain DRAFT until actual configured discovery/invocation and manifest-bound evaluation support activation through existing lifecycle transactions. No generic child is represented as a configured engineering lead.

Two executing specialists maximum, further reduced by host capacity and assignment limits. Parent plus two workers plus one reviewer fits four slots. Review follows frozen child outputs; reviewers own findings only, coordinator checks their artifacts and does not recursively review reviewers. Nested supervisors share the parent budget; no recursive delegation expansion. At most three correction cycles per dispatch unless an explicit smaller limit applies. Dependent work waits for accepted predecessor outputs. Ownership conflicts/required missing input/tool block dispatch. Failures propagate to the parent: the coordinator records the required child blocker in the parent TaskRecord.blockers before requesting completion, since the existing completion gate does not inspect child dependencies. The P04 CLI completion wrapper rejects task blockers; raw quality.completion_gate checks evidence only. Blocked-parent acceptance uses the actual CLI. Successful siblings remain saved. Cancellation stops children, preserves partial handoffs/history and leaves a terminal cancelled task; resume uses a new follow-up task. Interruption/failed resume refreshes revision, selection/preflight and evidence. Limits preserve remaining work rather than providing success.

## Acceptance criteria

| ID | Required result | Verification |
| --- | --- | --- |
| handoff_identity | Reject wrong task, stale revision and wrong role; accept current identity | Real filesystem unit tests |
| handoff_ownership | Exact owned files only, hashes/existence/root containment, independent of cwd | Unit tests including traversal, symlink, FIFO and tampering |
| handoff_coverage | Validate criterion IDs and existing local evidence, reject missing/duplicate outputs and incomplete ready coverage | Unit tests |
| child_failure | Blocked/failed required child keeps parent incomplete; preserved partial output and next step | Native blocked scenario and actual completion gate |
| bounded_execution | Two disjoint simultaneous specialists, scoped context and ownership; dependencies sequential; finite correction and cancellation rules | Installed-native trace and isolated scenarios |
| independent_integration | Each child and combined output independently reviewed; feedback resolved; fresh tests cover exact reviewed bytes | Native review and candidate-bound package review/checks |
| delegation_assets | Valid staged lead/skill, direct/indirect trigger, unrelated/missing-input/tool boundaries and genuine native discovery/invocation | Structural validators plus installed-client evaluation/manifests |
| preserved_state | P07 eligibility/proof unchanged, existing worktrees retained, local commits and accurate tracking/usage | Before/after hash and Git checks |
